# M1 后端框架与真实相机

本文说明命令行采集、录制与离线回放工具。日常监控和工时页面使用项目根目录的 `start.sh`，设备设置通过首页设置弹层调整。

## 启动

```bash
cd /home/seeed/workspace/jetson-worktime
.venv/bin/python scripts/run.py --config configs/station.m1.yaml --duration 60 --record-raw --output outputs/m1/new-run
```

每次使用新的输出目录，避免覆盖旧证据。`--duration 0` 表示持续运行；Ctrl+C 或 SIGTERM 会释放管线、封装录制片段、写出统计。相机网络连接为 `jetson-worktime-camera`，地址 192.168.1.250/24，禁止成为默认路由。需要重新激活时：`sudo nmcli connection up jetson-worktime-camera`。回滚网络连接：`sudo nmcli connection delete jetson-worktime-camera`；不影响管理网口。

RTSP_URL 从环境变量或项目 `.env` 获取，不在日志、配置、报告中保存凭据。不要提交 `.env`。当前相机 IP 192.168.1.10，实际媒体 H.265/2560×1440/20fps；密码不会显示在本文件。相机日期水印与主机当前日期不一致，不用于工时。

## 采集与回放

原始视频保存为 `raw-会话序号-分段序号.mp4`，每段上限约60秒。仅录制视频，不录音。异常断电时最后一个MP4片段可能不完整；正常退出与SIGTERM已提供封装清理。叠加视频是采样帧预览，不能用视频播放时长代替实际观察时间。真实时间使用JSONL中的PTS与本机单调时钟。

```bash
.venv/bin/python scripts/run.py --config configs/m1.replay.yaml --output outputs/m1/new-replay
```

`configs/m1.replay.yaml` 使用 `tests/fixtures/media/camera-h265.mp4` 中的本地测试片段，经过同一 Pose/ByteTrack/JSONL 入口。换片段时修改 source.path 和 codec。文件模式保留顺序帧并按媒体PTS采样；RTSP模式持续拉取解码帧，只保留一个最新帧槽位。覆盖数、采样跳过数、重复PTS数、退出丢弃数分别记录。GStreamer解码后队列与appsink也有界，录制分支使用独立有界队列。统计中的queue_depth指Python最新帧槽位。

无新帧时read有明确超时；独立监测线程每秒输出health.jsonl，不依赖推理线程拉帧。连续重复的非空PTS不算新观测，也不刷新新帧健康时间。没有PTS的帧依赖实际新sample和receive_sequence。流错误/超时后最多重连3次，退避1/2/4秒；失败后非零退出。重连或PTS倒退生成新session_id并重置tracker；人员身份应使用run_id/session_id/person_track_id组合，不能跨会话直接等同。

## ROI

先采集原图source.jpg，在原始像素坐标下设置多边形；尺寸变化时ROI观测返回无效，不自动缩放。region可为station/operation/infeed/outfeed。示例：

```bash
.venv/bin/python scripts/roi_config.py --image /path/to/source.jpg --output configs/roi-new.yaml --region 'station=0,0;2559,0;2559,1439;0,1439'
```

命令同时保存YAML和带标记截图。默认calibrated=false；只有现场确认后才使用`--confirm-calibrated`。将输出roi字段放到工位配置中。现有`configs/roi.m1.uncalibrated.yaml`和同名jpg只是整幅图的未标定示例。人在区域使用人体框底边中心作为参考；手腕仅在关键点置信度>=0.25时参与，缺失返回null。以上均为几何观测，不能直接认作有效工时。

## 输出及验证

- observations.jsonl：帧标识、流会话、接收序号、可空媒体PTS、接收/推理起止单调时间、原图BGR尺寸、人物框、轨迹ID、关键点及置信度、有效性、ROI观测。
- health.jsonl：每秒新帧健康、最新帧槽位、收帧/覆盖计数、RSS、CPU与系统可用内存。
- events.jsonl：脱敏的新会话、断流/超时事件。
- statistics.json：吞吐、分类丢弃、超时、重连、主机耗时分位数与资源趋势。
- source.jpg、annotated.jpg/mp4、stream.json：截图、叠加预览和协商尺寸/帧率。

本机耗时不等同于相机曝光到结果的端到端延迟。初始化峰值与运行状态需分别分析；短时RSS上涨含模型/CUDA初始化，不能据此声称泄漏或长时稳定。

## 设置与隐私版本的视频轨道选择

RTSP读取器通过`select-stream`信号及RTP caps显式选择配置对应的H.264或H.265视频轨道。相机发布的其他轨道会被筛除。联调中曾捕获`streaming stopped, reason not-linked (-1)`，因此加入上述筛选和回归测试，并在断流事件中保留脱敏后的GStreamer错误诊断。
